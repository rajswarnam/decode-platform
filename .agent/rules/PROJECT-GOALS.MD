## 1. Mission Statement
Build a VDI-compliant, agentic parsing engine that translates legacy C/COBOL and modern Java/React codebases into a semantic knowledge graph without using Docker or external cloud storage.

## 2. Measurable Technical Goals (Phase 1: Foundation)
*   **Hybrid Latency**: Achieve <200ms response time for local metadata queries (Postgres) and <50ms for vector search (Qdrant).
*   **VDI Cold Start**: The `setup-vdi.ps1` script must download, configure, and start Docker containers (MinIO/Qdrant) and verify Native Postgres connectivity in under 3 minutes.
*   **MCP Connectivity**: 100% of internal microservices must be discoverable via the Model Context Protocol (MCP) using stdio transport for local development.
*   **Token Efficiency**:
    *   **Utilization**: Achieve avg >85% quota utilization without ensuring a 429 error.
    *   **Priority Throughput**: 100% of "Business Critical" files must be summarized within the first 30 minutes.
    *   **Fault Tolerance**: System must resume from the exact last-processed file in the event of a throttle pause.

## 3. Data & Analysis Goals (Phase 2: Ingestion)
*   **Parsing Accuracy**: Tree-sitter must successfully extract at least 95% of symbols (functions, variables, library calls) from a sample 100k LOC legacy C repository.
*   **Semantic Clustering**: The Global Dictionary must identify and link at least 80% of semantically identical fields (e.g., ACCT_NUM vs. accountNumber) across subprojects.
*   **Ingestion Throughput**: The system must process and index code at a rate of 5,000 Lines of Code (LOC) per minute on a standard VDI worker node.
*   **Connectivity & Governance (Phase 2.5)**:
    *   **Proprietary Gateway**: Implement local LLM Gateway service.
    *   **Metric**: 0% Heuristic Fallbacks once Gateway active.


## 4. Success Criteria for Antigravity Agents
An agent's task is considered "Complete" only if:
*   **Hybrid-Docker Compliance**: All service interactions honor the split between Native (App/DB) and Docker (Vector/Object Store).
*   **Determinism Check**: Source code is normalized to LF and ONNX Runtime is used for embeddings.
*   **Auditability**: Every code summary generated by GPT-4o includes a direct reference to the file path and line numbers in the Documentation Hub.
*   **Dual-Storage Verification**: Code summaries exist in BOTH the `symbols` table (Postgres) and the Vector Store (Qdrant).
*   **Networking Verification**: "The host.docker.internal connection to Native Postgres is verified as part of the Phase 1 health check."
*   **Test Coverage**: All new MCP tool methods (@ToolCallback) include unit tests that achieve 80% line coverage.
